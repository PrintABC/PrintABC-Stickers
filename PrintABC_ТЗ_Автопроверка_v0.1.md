# ТЗ: Автопроверка макета наклеек — v0.1

**Назначение:** модуль принимает файл макета + параметры заказа, возвращает структурированный список проблем (JSON). Отчёт клиенту генерируется отдельным модулем из этого JSON.
**Принцип (Конституция, слой 4):** код измеряет, языковая модель оценивает визуально. Код никогда не «угадывает» цифры, модель никогда не выдаёт цифры клиенту.
**Стек:** Python. Библиотеки: PyMuPDF (fitz) — разбор PDF, Pillow — растр, pikepdf — цветовые пространства (при необходимости). Никаких экзотических зависимостей.

---

## Входные данные

```json
{
  "file": "path/to/file",                // PDF | PNG | JPG
  "order": {
    "width_mm": 50, "height_mm": 50,     // чистый размер наклейки
    "qty": 100,
    "shape": "rect | circle | oval | custom",
    "material": "paper | vinyl | polyester",
    "lang": "ru | he"
  }
}
```

**Константы (конфиг, не хардкод):**
```
BLEED_MM = 2.0          // вылет с каждой стороны
SAFE_MM  = 2.0          // отступ текста от линии реза
SIZE_TOL_MM = 0.5       // допуск на размер страницы
DPI_MIN = 300           // норма разрешения
DPI_WARN = 150          // ниже — ошибка, между — предупреждение
FONT_MIN_PT = 6.0       // минимальный кегль
RENDER_DPI = 150        // рендер PDF→PNG для визуальных проверок
```

## Конвейер проверок (по порядку, каждая пишет результат в общий JSON)

### CHECK 0 — Файл открывается и формат допустим
```
если расширение не в [pdf, png, jpg, jpeg] → FAIL "unsupported_format", стоп
попытаться открыть (fitz.open / PIL.Image.open)
  ошибка → FAIL "file_corrupt", стоп
если PDF и страниц > 1 → WARN "multipage", работаем с первой страницей
```

### CHECK 1 — Размер страницы (только PDF)
```
ожидаемый размер: EW = width_mm + 2*BLEED_MM; EH = height_mm + 2*BLEED_MM
page_w_mm = MediaBox.width / 72 * 25.4 (аналогично высота)
если |page_w_mm − EW| ≤ SIZE_TOL и |page_h_mm − EH| ≤ SIZE_TOL → PASS "size_with_bleed"
иначе если |page_w_mm − width_mm| ≤ SIZE_TOL и |page_h_mm − height_mm| ≤ SIZE_TOL
       → FAIL "no_bleed" (размер верный, вылетов нет)
иначе если пропорции совпадают (|page_w/page_h − EW/EH| ≤ 0.02)
       → WARN "wrong_size_same_ratio" (можно отмасштабировать самим)
иначе → FAIL "wrong_size" (указать фактический размер в мм)
Проверить также TrimBox: если задан и TrimBox ≠ MediaBox,
  bleed_mm = (MediaBox − TrimBox)/2 по каждой оси → сверить с BLEED_MM
```

### CHECK 2 — Размер и вылеты (растр PNG/JPG)
```
физического размера у растра нет → всегда FAIL "raster_no_dimensions",
  НО продолжить остальные проверки в предположении:
  масштаб = px_width / EW (клиент, скорее всего, рисовал «в чистый размер» — 
  проверить оба предположения: с вылетами и без, взять лучшее совпадение пропорций)
если пропорции файла ≠ пропорции заказа (>2%) → FAIL "ratio_mismatch"
Проверка вылетов эвристикой: сравнить среднее значение цвета рамки 
  шириной BLEED_MM (в px по масштабу) с центральной областью:
  рамка белая/пустая, центр цветной → вероятно нет вылетов → WARN "likely_no_bleed"
```

### CHECK 3 — Разрешение растровых изображений
```
PDF: для каждого image-объекта:
  eff_dpi = pixel_width / (placed_width_pt / 72)
  min_dpi = минимум по всем изображениям площадью > 5% страницы
Растровый файл: eff_dpi = px_width / (EW / 25.4)
если min_dpi ≥ DPI_MIN → PASS
если DPI_WARN ≤ min_dpi < DPI_MIN → WARN "low_dpi" (указать значение)
если min_dpi < DPI_WARN → FAIL "very_low_dpi"
```

### CHECK 4 — Безопасная зона (текст/объекты у края)
```
только PDF с живыми объектами:
safe_rect = страница, отступ (BLEED_MM + SAFE_MM) от каждого края
для каждого текстового блока (page.get_text("dict")) и векторного объекта:
  bbox выходит за safe_rect, но не является фоном 
  (фон = объект, покрывающий >90% страницы) → FAIL "content_near_edge"
  (в JSON — координаты bbox для обводки на скриншоте)
растр или текст кривыми → отдать LLM (CHECK 7)
```

### CHECK 5 — Кегль шрифта
```
только PDF с живым текстом:
для каждого span в page.get_text("dict"): собрать font_size (pt)
если min_size < FONT_MIN_PT → FAIL "font_too_small" (значение + bbox)
текст переведён в кривые (нет text-объектов, но LLM видит текст) → CHECK 7
```

### CHECK 6 — Цветовое пространство
```
определить: RGB / CMYK / смешанное (по объектам PDF или mode PIL)
RGB → WARN "rgb_colors" (НЕ FAIL: конвертируем сами, клиенту — 
  только предупреждение «оттенки могут отличаться от экрана»)
```

### CHECK 7 — Визуальные проверки (языковая модель)
```
рендер первой страницы в PNG (RENDER_DPI) → запрос к модели (Claude API) 
  с фиксированным промтом. Модель возвращает строго JSON:
{
  "readability": "ok | poor",          // читаемость на реальном размере (размер сообщить в промте)
  "ai_artifacts": "none | suspected",  // кривые буквы, искажённые детали (ЛЛМ-макет)
  "edge_content": "ok | suspected",    // важные элементы у края (для растра/кривых)
  "notes": "краткое описание находок"
}
правило: ответы модели попадают в отчёт ТОЛЬКО как формулировки без цифр;
  любые «suspected» → флаг manual_review для владельца
```

### CHECK 8 — Линия реза (только shape = custom)
```
искать в PDF спот-цвет с именем CutContour (или отдельный слой с вект. контуром)
найден → PASS
не найден → INFO "no_cutline" → маршрут «сделаем контур сами» 
  (НЕ ошибка клиента, не выносить в отчёт как проблему)
```

## Выход модуля

```json
{
  "verdict": "ready | fixable | manual_review | reject",
  "checks": [
    {"id": "no_bleed", "status": "FAIL", "measured": "50.0×50.0 мм",
     "expected": "54×54 мм", "bbox": null},
    ...
  ],
  "screenshot": "render.png",       // для обводок в отчёте
  "llm_visual": { ... }             // сырой ответ CHECK 7
}
```

**Правила вердикта:**
- FAIL > 3 → `reject` (макет проще переделать — отдельный разговор)
- 1–3 FAIL → `fixable` → генератор отчёта берёт до 3 блоков
- только WARN/INFO или «suspected» от модели → `manual_review` (владелец смотрит сам)
- всё PASS → `ready`

## Что модуль НЕ делает (границы v0.1)

- Не генерирует отчёт клиенту (отдельный модуль, вход — JSON выше)
- Не чинит файл (конвертация RGB→CMYK, построение контура — руками владельца, автоматизация позже)
- Не работает с AI/PSD/SVG — только PDF/PNG/JPG
- Не проверяет орфографию и дизайн

## Тесты приёмки (обязательны — Конституция, слой 4)

Набор из 15–20 реальных файлов из прошлых заказов с известным диагнозом
(размечает владелец). Модуль обязан совпасть с диагнозом владельца в ≥90%
проверок CHECK 0–6 (детерминированные). CHECK 7 — отдельная метрика,
допускается точность ниже, все «suspected» уходят на ручной просмотр.
